# 暮刻：整體產品審視與升級摘要

2026 年 8 月 27 日

## 結論

暮刻最適合保持「一個安靜、私人、打開就能用的日常助手」，而不是再加入帳戶、AI 或複雜健康追蹤。這次升級集中處理最常見的日常摩擦：首頁資訊分散、工時錯誤難以更正、完成待辦愈積愈多，以及本機資料和提醒能力不夠清楚。

## 已完成的升級

- 首頁新增「今天摘要」，集中顯示未完成待辦、今日活動、今日工時／收入和健身狀態。
- 摘要直接提供「新增活動」和「補錄工時」，並顯示下一項活動。
- 工時可切換月份、查看該月全部記錄、編輯錯誤資料、刪除記錄及防止重複輸入。
- 月份收入、堂／節數與總工時會跟隨所選月份重新計算。
- 待辦可逐項刪除，亦可一鍵清除已完成項目。
- 資料管理新增持久儲存請求、上次備份時間和儲存空間錯誤提示。
- 支援的主畫面 Web App 會在 App 圖示顯示未完成／到期項目的徽章數量。
- 放大主要觸控按鈕並恢復頁面縮放，改善單手操作與可讀性。
- 通知和香港假期說明改為準確、可驗證的描述。
- 新增暮刻專屬的連結分享封面。

## 為甚麼這樣改

Apple 說明 iOS／iPadOS 16.4 起，加入主畫面的 Web App 可使用 Web Push，而通知權限必須由使用者的直接操作觸發；主畫面 Web App 亦可使用 Badging API。因此暮刻採用主動開啟通知和能力偵測的 App 徽章，不在不支援的瀏覽器硬性承諾。[Web Push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) · [Badging](https://webkit.org/blog/14112/badging-for-home-screen-web-apps/)

本機瀏覽器資料通常先以 best-effort 模式儲存，網站可要求 persistent storage，但仍不能取代備份。因此資料管理同時提供持久儲存請求與 JSON 備份。[MDN：儲存配額與移除條件](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) · [MDN：`persist()`](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/persist)

觸控操作依照 WCAG 2.2 的目標尺寸原則放大，並移除禁止縮放的 viewport 設定，讓文字可以放大閱讀。[W3C：Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) · [W3C：Resize Text](https://www.w3.org/WAI/WCAG21/Understanding/resize-text.html)

香港假期沿用政府 1823 的官方 iCalendar 資料；官方頁面目前列出 2025–2027 年的資料範圍，所以 App 亦如實標示這個年份範圍。[香港政府 1823](https://www.1823.gov.hk/tc/hong-kong-public-holidays-ical)

## 使用建議

1. 在 iPhone Safari 開啟暮刻，按分享，再選「加入主畫面」。
2. 第一次使用先到右上角「本機」開啟資料保護。
3. 每月或更換手機前下載一次備份。
4. 需要在 App 關閉後可靠提醒的活動，使用「加入手機行事曆」。

暮刻繼續不連接 ChatGPT、不需要登入，個人內容留在目前裝置的瀏覽器內。
